# 季緣 CHIYUAN · HR 新人流程系統

新人報到、報到 Checklist、滿月考核、HR 總覽的線上化系統。可直接部署到 Cloudflare Pages。

## 頁面

| 檔案 | 用途 | 給誰用 |
|---|---|---|
| `index.html` | 新人報到（姓名＋門市比對雲端名冊，Checklist、學習資料） | 新進人員（主要入口） |
| `manager.html` | 店經理考核平台（新人考核＋技能評核入口，門市密碼保護） | 店經理 |
| `hr.html` | 跨門市總覽（報到進度、滿月待考核、考核結果） | HR（你，免密碼） |
| `items.html` | 新人考核項目說明（新人提前準備用） | 新進人員 |
| `skills.html` | 技能評核（占位頁，待需求說明後製作） | 店經理 |
| `assets/config.js` | **共用資料層：所有設定與雲端串接都集中在這裡** | 設定用 |
| `functions/api/roster.js` | 讀雲端名冊的後端代理（金鑰藏後端） | 部署用 |
| `functions/api/eval.js` | 考核結果寫回雲端的後端代理 | 部署用 |
| `functions/api/checkin.js` | 新人自報（待核對）寫回雲端的後端代理 | 部署用 |

## 目前狀態

- 現在用 `config.js` 內建的**名冊樣本**運作，可完整預覽所有流程。
- 尚未接雲端（`USE_CLOUD: false`）。拿到金鑰後照下面設定即可切換。

## 接雲端試算表

完整規劃見 **`雲端串接規劃.md`**（架構、試算表分頁欄位、資料流、舊資料接回、部署步驟、待你提供項目）。

簡述：讀寫全部走**單一 Apps Script Web App**（`apps-script/Code.gs`），Cloudflare Functions 只負責轉發、金鑰藏在後端。

上線三步：
1. `apps-script/Code.gs` 填 `SHEET_ID` → 部署成網頁應用程式，複製網址。
2. Cloudflare Pages 環境變數新增 `APPS_SCRIPT_URL` = 該網址。
3. `assets/config.js` 的 `USE_CLOUD` 改成 `true` → 部署。

（切 true 前用內建樣本即可完整預覽；切 true 後全部改走雲端。）

## 行為重點

- **新人登入**：姓名＋門市＋職位，比對雲端名冊；查無資料顯示「待 HR 建立」。
- **店經理考核**：15 項五級 100 分，**達 70 分才能送出**；未達標無法送出，代表需持續培訓，日後可再登入重新評核，合格再送出。
- **待核對**：新人自勾但雲端未登記的項目，會在 HR／店經理頁顯示「待核對」，提醒你去確認並在雲端標記。
- **技能評核資料保留**：評核存在瀏覽器（localStorage `skill_eval_v2`），重開頁面不會清空、不用重新登入。（換裝置／清快取才會不見，接雲端後才跨裝置永久保存。）
- **新人考核 ↔ 技能評核 優先順序**：對應到的技能項目，以「較新的那份考核」為準（比較新人考核日 vs 該人技能評核最後更新日）。新人考核較新→自動帶入並標「新人考核帶入（可改）」；技能評核較新→保留，店經理月檢視改了就變最新。空白項一律補。此帶入需技能評核向新人考核取資料，接 Cloudflare 後走 `/api` 才會實際互通。

## 門市密碼（最後定案再啟用）

`config.js` 的 `STORE_PW` 填各門市密碼，例：`{ "一中店":"cy1234" }`。
沒填的門市＝測試模式免密碼。HR 總覽頁不設密碼。
（依你的規劃：密碼與正式發佈等全部定案後再一次設定。）

## 部署到 Cloudflare Pages

1. 把整個資料夾推到 GitHub（或用 Wrangler / 直接上傳）。
2. Cloudflare Pages → 建立專案 → 連結該 repo。
3. Build 設定：**框架 = None、輸出目錄 = /（根目錄）**，無需建置指令。
4. 設定上面的環境變數 → 部署。

> 建議：全部頁面做好、確認無誤後再第一次部署，避免反覆觸發。
