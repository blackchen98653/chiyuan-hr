# 戰情室技能覆蓋分析 — 對齊指令

> 貼到「季緣人力戰情室」那個對話，請對方 cowork 依此修改。
> 目的：讓戰情室的技能等級與覆蓋率，和「季緣 SM 技能評核」完全一致。
> 現況問題：兩邊對不上，店經理評的「需協助 / 熟練」在戰情室會被丟掉、覆蓋率也算錯。

---

請把戰情室（季緣人力戰情室 v5_11）的技能邏輯，對齊成與「SM 技能評核」一致的標準：

## 1. 技能總數 = 28 項
戰情室已有 `frontline（前場應變）`，維持即可、不用加。
所有覆蓋率 / 等級的分母，一律用 `ALL_SKILL_KEYS.length`，**不要再出現寫死的 24 / 25 / 26**（`skillScoreSum` 註解「0~24」、`LEVEL_BANDS` 停在 26 都要改）。

## 2. 等級改成 5 級（key、標籤、權重務必完全一致）

| key | 標籤 | 權重 |
|---|---|---|
| rusty | 未接觸 | 0.0 |
| basic | 需協助 | 0.4 |
| normal | 可獨立 | 0.75 |
| skilled | 熟練 | 0.9 |
| expert | 精熟 | 1.0 |

對應要改的函式：

- `LEVEL_WEIGHTS = {rusty:0, basic:0.4, normal:0.75, skilled:0.9, expert:1.0}`
- `LEVELS`（標籤/顏色）補齊成上表 5 級（目前只有 3 級：expert/normal/rusty，且名稱是熟練/學習中/未具備，要改掉）。
- `skillVal(v)`：要接受 `rusty / basic / normal / skilled / expert` 五個值（`true` 仍當 `expert`），其餘才回 `''`。**不可再把 basic / skilled 濾成空字串**（這是目前資料消失的主因）。
- `isSkilled(v)`（算「掌握」）：`normal / skilled / expert` 為掌握；`rusty`、`basic` 不算。
- `isAnyLevel(v)`（算「有評過」）：五級都算（含 rusty、basic）。
- `LEVEL_BANDS`（員工等級 Lv）：以 28 為基準重新分級，或改用「掌握比例」分級，不要停在 26=MAX。

## 3. 覆蓋率 `getStoreCoverage`
分母 `withSkills.length * ALL_SKILL_KEYS.length`（=28）本身正確；只要 numerator 改用新的 `isSkilled` 即可。

## 4. 驗收
改完後，店經理在技能評核送出的「需協助 / 可獨立 / 熟練 / 精熟」都要能在戰情室完整吃進、覆蓋率正確，不再有評分憑空消失的情況。
